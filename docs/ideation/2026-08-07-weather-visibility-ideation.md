# Ideation: 全国地图的晴雨可见性

## Codebase Context

「晴域」当前是 React + TypeScript + Vite + ECharts 的全国天气地图，约 370 个城市点。
首屏为七日总览，点位颜色/形状表达晴雨状态，主要城市标签显示 `x/7`，并有“有晴窗”
筛选、日期切换、城市搜索和详情面板。

当前的主要问题不是天气数据不足，而是视觉注意力仍然分散在很多小点上：用户需要先理解
图例，再读标签，才能形成“哪一大片区域更适合继续看”的空间判断。

## Ranked Ideas

### 1. 晴雨区域底色 + 城市点双层编码

**Description:** 在省级行政区下增加一层基于城市样本的晴雨底色：当前选定日期用“无雨城市
比例”，七日总览用“城市平均无雨天数”映射为浅到深的连续明度。无雨城市点在上层使用暖白/金色
光晕，有雨城市降为冷蓝灰和低透明度；所有点仍可点击。

**Rationale:** 远景先看区域，近景再看城市，完全符合全国地图的两级阅读路径。用户不必先读
数字就能看到“哪一片更亮”，同时不会失去具体城市的精确天气。

**Downsides:** 区域底色是城市样本汇总，不是逐公里雷达边界；必须在图例和说明中明确这一点。

**Confidence:** 95%

**Complexity:** Medium

**Status:** Explored — implemented in the first visual iteration

### 2. 突出无雨模式升级为“有晴窗”筛选

**Description:** 筛选开关开启后，默认突出至少连续 2 天无明显降水的城市，并允许切换为连续
3/4 天。未满足条件的城市保留在地图上但降为低透明度；顶部同步显示规则和匹配城市数。

**Rationale:** “晴窗”直接对应用户“未来一周内找几天不下雨”的需求，比笼统的晴区模式更容易
解释；用户可以先扫全国，再用城市标签或详情面板确认细节。

**Downsides:** 连续天数不是目的地推荐分数；必须明确它只是机械筛选，未知数据不能算作无雨。

**Confidence:** 91%

**Complexity:** Low–Medium

**Status:** Implemented — final MVP interaction

### 3. 连续无雨天数作为核心指标

**Description:** 在 `x/7` 之外显示“最长连续无雨 3 天”，并用外圈厚度或光晕强度表达连续性。
地图仍不排序、不推荐，只把每个城市的机械统计变得更贴近用户的实际判断。

**Rationale:** `5/7` 可能是零散晴天，也可能是连续五天；连续性对“未来任意几天能不能去”更
有信息量，而且比引入旅游评分更克制。

**Downsides:** 需要同时显示起止日期，避免用户误以为连续晴天从今天开始。

**Confidence:** 88%

**Complexity:** Low–Medium

**Status:** Implemented — used by “有晴窗” and shown in city details

### 4. 七日晴雨胶囊

**Description:** 放大后，城市标签由单个 `x/7` 变成七个极小的日格：暖色表示无雨，蓝色表示
有雨，灰色表示未知；远景仍只保留一个明度和 `x/7`。

**Rationale:** 用户可以区分“连续晴”和“零散晴”，不必打开详情；日期维度直接可见。

**Downsides:** 全国远景会过载，必须严格依赖缩放分级；手机端不宜默认展示。

**Confidence:** 82%

**Complexity:** Medium–High

**Status:** Unexplored

### 5. 区域机械摘要

**Description:** 在华北、华东、西南等大区的地图边缘放置非推荐性的摘要徽标，例如“18/31 城市
今日无雨 · 最长连续 4 天”，点击后只聚焦地图，不生成目的地排序。

**Rationale:** 在全国尺度先回答“往哪个方向看”，再用城市点回答“具体是哪座城”，对手机小屏
尤其有帮助。

**Downsides:** 大区划分属于产品定义，容易被误解为目的地排名；文案必须使用“区域数据摘要”，
不能出现“最佳目的地”。

**Confidence:** 77%

**Complexity:** Medium

**Status:** Unexplored

### 6. 七日逐日扫图

**Description:** 日期条支持连续拖动，地图随日期轻微过渡，观察晴区如何移动；默认停在用户手动
选择的日期，不自动播放。

**Rationale:** 能表达“哪天、哪一片区域晴”，比固定的七日总览更适合临时决定出发日。

**Downsides:** 动画会增加理解成本，必须支持减少动态，并把日期固定显示在地图标题附近。

**Confidence:** 74%

**Complexity:** Medium

**Status:** Unexplored

## Rejection Summary

| Idea | Reason rejected or deferred |
|---|---|
| 插值“晴区”连续面 | 容易被误解为精确降雨边界；先用省级/区域样本底色更诚实。 |
| 纯光晕强化 | 只能解决点的注意力，不能解决全国尺度的空间聚合；并入双层编码。 |
| 仅增加更亮的金色 | 色彩数量和亮度不是信息层次，容易变成装饰；必须和区域聚合、图例一起使用。 |
| 自动循环播放七日天气 | 用户容易错过日期语义；先保留手动日期切换，逐日扫图作为后续增强。 |
| “晴岛”命名和目的地聚类 | 会把机械天气地图带向推荐产品，且地理聚类边界解释成本高。 |

## Recommended Sequence

第一阶段采用 1 + 2：区域底色提供远景答案，“有晴窗”用连续无雨天数强化无雨点位；同时把
`x/7` 与最长连续无雨天数保留在城市详情里。4 和 5 暂不加入，不建议第一版同时加入自动动画
和聚类。
